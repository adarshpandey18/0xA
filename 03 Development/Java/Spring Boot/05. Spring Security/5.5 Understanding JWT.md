
# Understanding JWT (JSON Web Token)

## Why use JWT?

1. **Stateless** – no server-side session needed.
    
2. **Scalable in Distributed Systems** – works well in microservices.
    
3. **Cross-Domain Authentication** – useful in APIs and SPAs.
    
4. **Decentralized Systems** – independent of a central auth server.
    
5. **Secure & Compact** – tamper-proof, URL-safe, lightweight.
    

---

## What is JWT?

- A **compact, URL-safe token** used to securely transmit claims between two parties.
    
- Commonly used for **authentication & authorization**.
    
- Provides **integrity and authenticity** (not encryption by default).
    
- Ideal for storing **non-sensitive** but important claims like:
    
    - User ID
        
    - Roles
        
    - Permissions
        
    - Expiration time
        

>  Don’t store **passwords or highly sensitive data** inside JWT.

---

##  Structure of a JWT

JWT has **3 parts** separated by dots (`.`):

```
header.payload.signature
```

### 1. **Header**

Contains metadata about the token, including signing algorithm.

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

### 2. **Payload**

Holds claims (user info, metadata). Example:

```json
{
  "id": 1,
  "name": "Adarsh Pandey",
  "role": "ADMIN",
  "exp": 1735678900
}
```

### 3. **Signature**

- Created by hashing **Header + Payload** with the **Secret Key**.
    
- Ensures **integrity**: if payload is tampered, signature won’t match.
    

```text
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

---

##  JWT Verification

1. Client sends token in `Authorization: Bearer <token>`.
    
2. Server decodes token → verifies signature with secret.
    
3. If valid → extract claims (`id`, `roles`, etc.).
    
4. If expired/invalid → reject request.

### 2. JWT Service Example

```java
@Service
public class JWTService {

    @Value("${jwt.secretkey}")
    private String jwtSecretKey;

    private SecretKey getSecretKey() {
        return Keys.hmacShaKeyFor(jwtSecretKey.getBytes(StandardCharsets.UTF_8));
    }

    public String generateToken(User user) {
        return Jwts.builder()
                .subject(user.getId().toString()) // unique identifier
                .claim("email", user.getEmail())
                .claim("roles", Set.of("ADMIN", "USER"))
                .issuedAt(new Date())
                .expiration(new Date(System.currentTimeMillis() + 1000 * 60 * 60)) // 1 hour
                .signWith(getSecretKey())
                .compact();
    }

    public Long getUserIdFromToken(String token) {
        Claims claims = Jwts.parser()
                .verifyWith(getSecretKey())
                .build()
                .parseSignedClaims(token)
                .getPayload();

        return Long.valueOf(claims.getSubject());
    }
}
```

##  Best Practices

- Use **HTTPS** to prevent token interception.
    
- Store JWT in **HTTP-only cookies** or **secure storage** (avoid localStorage in production).
    
- Keep tokens **short-lived** (e.g., 15m) → use **refresh tokens**.
    
- Always validate **signature & expiration** before trusting claims.
    
- Don’t put sensitive data inside JWT payload.
