# Security Attacks

## 1. Cross-Site Request Forgery (CSRF)

- **Definition**: Tricks an authenticated user into unintentionally performing actions on a web app (e.g., fund transfer) without their consent.
    
- **Cause**: Exploits trust between the **web application** and the **user’s browser**.
    

**Example**  
If a banking site lacks CSRF protection, an attacker can embed a malicious form that silently triggers a money transfer when the user is logged in.

**Prevention**:

1. Use **CSRF tokens** – Generate unpredictable, unique tokens for each user session and validate them with each request.
    
2. Go **stateless with JWT** – Manage authentication using signed JWT tokens instead of relying on session state.
    
3. Enforce **SameSite cookies** to reduce CSRF risks.
    

---

## 2. Cross-Site Scripting (XSS)

- **Definition**: Occurs when attackers inject **malicious scripts** into web pages, executed in other users’ browsers.
    
- **Impact**: Can steal cookies, hijack sessions, deface websites, or perform unauthorized actions.
    

**Example**

```html
<script>alert('XSS');</script>
```

Injected into a comment field → executed whenever another user views the comment.

**Prevention**:

1. **Input Validation** – Reject/escape dangerous characters before storing (use libraries/framework validation).
    
2. **Output Encoding** – Encode output before rendering in the browser (e.g., `HtmlUtils.htmlEscape(userInput)` in Spring).
    
3. Use **Content Security Policy (CSP)** headers to restrict script execution.
    

---

## 3. SQL Injection

- **Definition**: Allows attackers to inject **malicious SQL** into queries via input fields.
    
- **Impact**: Can read, modify, or delete sensitive data.
    

**Example**  
Intended query:

```sql
SELECT * FROM users WHERE username = 'input';
```

Attacker input:

```sql
' OR '1'='1
```

Resulting query:

```sql
SELECT * FROM users WHERE username = '' OR '1'='1';
```

→ Returns all users (authentication bypass).

**Prevention**:

1. Always use **prepared statements** / **parameterized queries**.
    
    ```java
    PreparedStatement stmt = conn.prepareStatement("SELECT * FROM users WHERE username = ?");
    stmt.setString(1, userInput);
    ```
    
2. Use **ORM frameworks** (e.g., JPA, Hibernate) instead of raw SQL.
    
3. **Validate & sanitize inputs** – Reject suspicious patterns.
    
4. Apply **principle of least privilege** for DB users.
