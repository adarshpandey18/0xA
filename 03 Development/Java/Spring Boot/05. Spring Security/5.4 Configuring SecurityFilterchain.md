# Configuring `SecurityFilterChain`

By configuring the **security filter chain**, we can:

- Add custom filters
    
- Remove default filters
    
- Whitelist endpoints
    
- Enforce role-based access control
    
- Configure authentication and sessions
    

This allows us to override Spring Security defaults and adapt it for JWT, APIs, or custom login flows.

---

## Example Config

```java
@Configuration
@EnableWebSecurity // Correct annotation, not @EnableSecurity
public class WebSecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            // Login configuration (optional if using JWT instead)
            .formLogin(form -> form
                .loginPage("/index.html") // Custom login page
                .permitAll()
            )
            // Request authorization
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/post").permitAll() // Public endpoint
                .requestMatchers("/posts/**").hasRole("ADMIN") // Only ADMIN can access
                .anyRequest().authenticated() // Everything else requires authentication
            )
            // Disable CSRF for APIs (JWT typically used)
            .csrf(csrf -> csrf.disable())
            // Stateless session (for JWT-based auth)
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            .build();
    }

    // In-memory users for testing
    @Bean
    public UserDetailsService userDetailsService(PasswordEncoder passwordEncoder) {
        UserDetails normalUser = User.withUsername("adarsh")
            .password(passwordEncoder.encode("Adarsh123"))
            .roles("USER")
            .build();

        UserDetails adminUser = User.withUsername("ayush")
            .password(passwordEncoder.encode("ayush@123"))
            .roles("ADMIN")
            .build();

        return new InMemoryUserDetailsManager(normalUser, adminUser);
    }

    // Password encoder
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

---

## Key Notes

- **Annotation** → Use `@EnableWebSecurity` instead of `@EnableSecurity`.
    
- **PasswordEncoder** → Must use a strong encoder like `BCryptPasswordEncoder`.
    
- **Session Policy**:
    
    - `ALWAYS`: Always creates a session
        
    - `NEVER`: Never creates a session, but can use existing one
        
    - `IF_REQUIRED` (default): Creates a session only if needed
        
    - `STATELESS`: No session at all (recommended for JWT APIs)
        
- **formLogin()** → Used for web apps with login forms. For APIs with JWT, this is usually disabled.
    
- **requestMatchers()** → Controls access per endpoint/HTTP method. Example:
    
    ```java
    .requestMatchers(HttpMethod.GET, "/public/**").permitAll()
    ```
    

---

## JWT vs FormLogin

- **FormLogin** → For browser-based apps, relies on session cookies.
    
- **JWT** → For APIs/mobile apps, stateless, scalable, and doesn’t require session storage.
    

In production APIs, you’d usually **disable formLogin()** and configure a JWT filter instead.
