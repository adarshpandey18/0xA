# Internal Working of Spring Security

## 1. Adding Spring Security

In a Spring Boot application, you only need to include the **spring-boot-starter-security** dependency.  
Spring Boot auto-configures security with **sensible defaults** in `WebSecurityConfiguration`.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

---

## 2. Authentication vs Authorization

- **Authentication** → Verifies _who_ the user is (identity check).  
    Example: Username + Password validation.
    
- **Authorization** → Verifies _what_ the authenticated user can do (access control).  
    Example: A `ROLE_ADMIN` can delete users, but a `ROLE_USER` cannot.
    

---

## 3. Internal Workflow of Spring Security

When a request comes into a secured Spring Boot app:

1. **Request → `DelegatingFilterProxy`**
    
    - Spring Boot auto-registers a filter named `springSecurityFilterChain`.
        
    - `DelegatingFilterProxy` delegates requests to the Spring-managed `FilterChainProxy`.
        
2. **`FilterChainProxy` → `SecurityFilterChain`**
    
    - `SecurityFilterChain` decides which filters should run for the current request.
        
    - Example filters: `UsernamePasswordAuthenticationFilter`, `BasicAuthenticationFilter`, `CsrfFilter`, etc.
        
3. **Authentication Manager**
    
    - Uses `AuthenticationProvider` implementations (e.g., DAO Authentication Provider).
        
    - Delegates to `UserDetailsService` (your `UserService`) to load the user from DB.
        
4. **Password Encoding**
    
    - Compares the stored hashed password with the provided credentials using `PasswordEncoder` (e.g., BCrypt).
        
5. **SecurityContext**
    
    - If authentication is successful, an `Authentication` object is stored in `SecurityContextHolder`.
        
6. **Authorization**
    
    - Once authenticated, Spring checks roles/authorities before allowing access to endpoints (`@PreAuthorize`, `@Secured`, `HttpSecurity` rules).
        

 Diagram (simplified request flow):

```
Request
   ↓
DelegatingFilterProxy (springSecurityFilterChain)
   ↓
FilterChainProxy
   ↓
Security Filters (CSRF → Auth → Session → etc.)
   ↓
Authentication Manager
   ↓
Authentication Provider (e.g., DAOAuthProvider)
   ↓
UserDetailsService (load user from DB)
   ↓
PasswordEncoder (verify password)
   ↓
SecurityContextHolder (store Authentication)
   ↓
Access Decision Manager (check roles/authorities)
   ↓
Controller (if authorized)
```

## 4. Default Behaviour of Spring Security

Without any custom configuration:

- Registers `springSecurityFilterChain` for all requests.
    
- Enables **HTTP Basic Auth** by default.
    
- Generates a **default login form**.
    
- Creates a default user:
    
    - Username → `user`
        
    - Password → printed in console on startup.
        
- Passwords stored using **BCrypt**.
    
- Enables **logout** at `/logout`.
    
- CSRF protection enabled.
    
- Session fixation protection enabled.
    

Example login:

```
Username: user
Password: <printed in console>
```

---

## 5. Changing Default Username & Password

Set credentials in `application.properties`:

```properties
spring.security.user.name=adarsh
spring.security.user.password=password
spring.security.user.roles=USER
```
