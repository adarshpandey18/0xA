# Spring Security Exception Handling

Spring Security throws different exceptions during **authentication** and **authorization**.  
You should handle them properly and return the correct **HTTP status code + JSON error response**.

---

## 1. `AuthenticationException` (Spring Security)

Parent exception for authentication failures.  
Default status → **401 Unauthorized**

Common subclasses:

- `BadCredentialsException` → Wrong username or password
    
- `AccountExpiredException` → Account validity expired
    
- `CredentialsExpiredException` → Password expired
    
- `AuthenticationCredentialsNotFoundException` → Missing credentials
    
- `SessionAuthenticationException` → Session-related issue
    

 Typically handled via `AuthenticationEntryPoint`.

---

## 2. JWT Exceptions

When using **JJWT** or similar libraries, token parsing can throw:  
Default status → **401 Unauthorized**

- `ExpiredJwtException` → Token is expired
    
- `MalformedJwtException` → Token structure is invalid
    
- `SignatureException` → Token signature doesn’t match secret key
    
- `UnsupportedJwtException` → Token type/algorithm not supported
    
- `IllegalArgumentException` → Token string is null/empty
    

---

## 3. Authorization Exceptions

When user is **authenticated but lacks permission**.  
Default status → **403 Forbidden**

- `AccessDeniedException` → User doesn’t have required role/authority
    

 Typically handled via `AccessDeniedHandler`.

---

## 4. Implementation Example

### Global Exception Handling in Spring Security Config

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .exceptionHandling(ex -> ex
                // Authentication (401)
                .authenticationEntryPoint((request, response, authException) -> {
                    response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
                    response.setContentType("application/json");
                    response.getWriter().write("{\"error\": \"Unauthorized\", \"message\": \"" 
                                               + authException.getMessage() + "\"}");
                })
                // Authorization (403)
                .accessDeniedHandler((request, response, accessDeniedException) -> {
                    response.setStatus(HttpServletResponse.SC_FORBIDDEN);
                    response.setContentType("application/json");
                    response.getWriter().write("{\"error\": \"Forbidden\", \"message\": \"" 
                                               + accessDeniedException.getMessage() + "\"}");
                })
            )
            .build();
    }
}
```

## 5. Handling JWT Parsing Errors

When parsing JWT inside your `JwtFilter`, wrap it in `try–catch`:

```java
try {
    Claims claims = Jwts.parser()
            .verifyWith(getSecretKey())
            .build()
            .parseSignedClaims(token)
            .getPayload();
} catch (ExpiredJwtException e) {
    throw new AuthenticationServiceException("Token expired", e);
} catch (MalformedJwtException | SignatureException | IllegalArgumentException e) {
    throw new AuthenticationServiceException("Invalid token", e);
}
```

This way, Spring Security’s `AuthenticationEntryPoint` will catch it and return **401 Unauthorized** with a JSON message.

---
- **AuthenticationException** → 401 Unauthorized
    
- **JWT Exceptions** → 401 Unauthorized
    
- **Authorization (AccessDenied)** → 403 Forbidden
