# Logging 

---

## 1. What is Logging?

- **Logging** is the process of recording events during application execution.
    
- Helps developers trace issues, debug crashes, and monitor application flow.
    
- Spring Boot provides **built-in logging support** via **SLF4J + Logback** (default).
    

---

## 2. SLF4J (Simple Logging Facade for Java)

- Acts as a **logging abstraction layer**.
    
- Allows switching between different logging frameworks (`Log4j`, `Logback`, `java.util.logging`, `tinylog`, etc.) without changing application code.
    
- Spring Boot internally uses **SLF4J + Logback** by default.
    

With SLF4J you write:

```java
private static final Logger log = LoggerFactory.getLogger(MyClass.class);

log.info("This is an info message");
log.warn("This is a warning");
log.error("This is an error");
```

But you can swap Logback with Log4j2 or JUL just by changing dependencies.

---

## 3. Elements of a Logging Framework

Every logging framework (Logback, Log4j2, JUL) has 3 components:

1. **Logger** → Captures log messages.
    
2. **Formatter/Layout** → Defines log message format (date, thread, level, etc.).
    
3. **Appender/Handler** → Defines where logs are written (console, file, DB, email, etc.).
    

---

## 4. Log Levels in Spring Boot

Spring Boot supports **6 standard log levels**:

1. `FATAL` → Severe errors that cause system crash.
    
2. `ERROR` → Runtime errors.
    
3. `WARN` → Potential problems.
    
4. `INFO` → General runtime events.
    
5. `DEBUG` → Detailed system flow information.
    
6. `TRACE` → Most detailed diagnostic info.
    

 Example usage:

```java
log.error("Error log");
log.warn("Warning log");
log.info("Info log");
log.debug("Debug log");
log.trace("Trace log");
```

>  Note: `log.fatal()` is not present in SLF4J; you normally use `log.error()` for fatal cases.

---

## 5. Setting Log Levels

Configure in `application.properties`:

```properties
# Set root log level
logging.level.root=INFO  

# Set package-specific log level
logging.level.com.myproject=DEBUG  
logging.level.org.springframework.web=ERROR
```

 Behavior:

- If you set `logging.level.root=WARN` → only `WARN, ERROR, FATAL` logs appear.
    
- Lower levels (`INFO, DEBUG, TRACE`) will not be shown.
    

---

## 6. Log Formatting

Customize log output format:

```properties
logging.pattern.console=%d{yyyy-MM-dd HH:mm:ss} [%level] %c{1} [%t] - %m%n
```

**Placeholders:**

- `%d` → Date/time
    
- `%level` → Log level
    
- `%c` → Logger name (class)
    
- `%t` → Thread name
    
- `%m` → Message
    
- `%n` → Newline
    

Example output:

```
2025-08-24 12:01:32 [INFO] MyService [main] - User created successfully
```

## 7. Logback in Spring Boot

Spring Boot uses **Logback** as the default logging implementation.

### Override Logback Configurations

Create `src/main/resources/logback-spring.xml`:

```xml
<configuration scan="true">

    <!-- Console Appender -->
    <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- File Appender -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/app-%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- Logger -->
    <logger name="com.myproject" level="DEBUG" additivity="false">
        <appender-ref ref="STDOUT"/>
        <appender-ref ref="FILE"/>
    </logger>

    <!-- Root Logger -->
    <root level="INFO">
        <appender-ref ref="STDOUT"/>
    </root>
</configuration>
```

👉 With this config:

- Logs go both to **console** and **logs/app.log**.
    
- Old logs rotate daily (`app-YYYY-MM-DD.log`).

## 8. Production Logging Best Practices

- Use **INFO** in production, **DEBUG/TRACE** only in dev.  
- Store logs in **files**, not just console.  
- Use **rolling log files** (to prevent disk overflow).  
- Ship logs to centralized systems (e.g., **ELK stack (Elasticsearch, Logstash, Kibana)** or **Grafana Loki**).  
- Mask sensitive data (passwords, tokens) before logging.

---

 So, in a **high-level Patient Management System**, you’d configure Logback with:

- Separate loggers for modules (`patient`, `billing`, `appointments`).
    
- File + Console appenders.
    
- WARN+ERROR for third-party libs, DEBUG for your app.
    
- Integration with ELK/Grafana for monitoring.
